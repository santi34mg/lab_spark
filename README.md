* `src/`: Python source code for this project.
  * `src/lab_databricks/`: Shared Python code that can be used by jobs and pipelines.
* `resources/`:  Resource configurations (jobs, pipelines, etc.)
* `tests/`: Unit tests for the shared Python code.
* `fixtures/`: Fixtures for data sets (primarily used for testing).


## Capa gold y dashboard

El job `gold_transform` ([resources/gold_transform.job.yml](resources/gold_transform.job.yml)) agrega las tablas
silver en el schema `gld_stm`. Los notebooks están en `src/notebooks/gold/`; las reglas compartidas (tipo de día,
franjas horarias, día típico, ventanas de análisis) están en `gold_comun.py`.

| Tabla | Grano | Para qué |
|---|---|---|
| `demanda_diaria` | fecha × empresa × grupo × tipo de viaje × tipo de tramo | cubo base de demanda |
| `demanda_dia` | fecha | total, valor esperado y días atípicos (feriados, paros, elecciones) |
| `demanda_mensual` | mes × tipo de día × categoría de usuario | evolución y recuperación vs. pre-pandemia |
| `demanda_hora`, `perfil_horario` | fecha × hora / año × tipo de día × hora | semana típica y forma del día |
| `dim_grupo_usuario`, `dim_tipo_viaje` | código | una descripción por código + categoría |
| `lineas_mensual` | mes × línea × tipo de día | demanda por línea |
| `oferta_demanda_linea` | línea × tipo de día × franja | subidas por salida programada (horario vigente) |
| `paradas_espera` | parada | refugio, demanda, horas-persona de espera a la intemperie |
| `transbordos_mensual`, `transbordos_minutos`, `transbordos_pares` | mes / tramo de minutos / par de líneas | transbordos reconstruidos por viaje |
| `calidad_mensual` | mes | linaje y calidad entre bronze y silver |

Decisiones de modelado:
- **Subida** = una fila de `viajes` (un tramo). **Viaje** = subida inicial (efectivo u `ordinal_de_tramo` 1).
- Los promedios son por **día típico**: un día es atípico si se aparta más de 25% de la mediana del mismo día de
  la semana ±4 semanas. Así se detectan feriados, paros y elecciones sin calendario externo.
- La recuperación compara el mismo mes calendario contra nov-2019 a feb-2020 (la única base pre-pandemia).
- Horarios y paradas son una foto actual: se cruzan con los últimos 2 meses (oferta) o 12 meses (paradas,
  transbordos). Subidas por salida no es ocupación: la fuente no tiene bajadas.
- Espera estimada por subida = mitad del intervalo programado de su variante en esa parada y franja, con tope de
  15 minutos y 0 en la cabecera.
- Un mes con menos de 5% de transbordos es una falla de la fuente (jun-2022) y no se usa como referencia.

El dashboard ([resources/stm_movilidad.dashboard.yml](resources/stm_movilidad.dashboard.yml),
`src/dashboards/stm_movilidad.lvdash.json`) se despliega con el bundle y lee solo tablas gold.

```
$ databricks bundle deploy
$ databricks bundle run gold_transform
```

Si el deploy falla porque el volume `viajes` ya existe (lo creó el deploy de otro integrante), vinculalo una vez:
`databricks bundle deployment bind viajes lab_spark.brz_stm.viajes`.


## Getting started

Choose how you want to work on this project:

(a) Directly in your Databricks workspace, see
    https://docs.databricks.com/dev-tools/bundles/workspace.

(b) Locally with an IDE like Cursor or VS Code, see
    https://docs.databricks.com/dev-tools/vscode-ext.html.

(c) With command line tools, see https://docs.databricks.com/dev-tools/cli/databricks-cli.html

If you're developing with an IDE, dependencies for this project should be installed using uv:

*  Make sure you have the UV package manager installed.
   It's an alternative to tools like pip: https://docs.astral.sh/uv/getting-started/installation/.
*  Run `uv sync --dev` to install the project's dependencies.


# Using this project using the CLI

The Databricks workspace and IDE extensions provide a graphical interface for working
with this project. It's also possible to interact with it directly using the CLI:

1. Authenticate to your Databricks workspace, if you have not done so already:
    ```
    $ databricks configure
    ```

2. To deploy a development copy of this project, type:
    ```
    $ databricks bundle deploy --target dev
    ```
    (Note that "dev" is the default target, so the `--target` parameter
    is optional here.)

    This deploys everything that's defined for this project.
    For example, the default template would deploy a job called
    `[dev yourname] lab_databricks_job` to your workspace.
    You can find that resource by opening your workpace and clicking on **Jobs & Pipelines**.

3. Similarly, to deploy a production copy, type:
   ```
   $ databricks bundle deploy --target prod
   ```
   Note that the default job from the template has a schedule that runs every day
   (defined in resources/sample_job.job.yml). The schedule
   is paused when deploying in development mode (see
   https://docs.databricks.com/dev-tools/bundles/deployment-modes.html).

4. To run a job or pipeline, use the "run" command:
   ```
   $ databricks bundle run
   ```

5. Finally, to run tests locally, use `pytest`:
   ```
   $ uv run pytest
   ```
